## 一句话

有据是一本给你依据的答案之书：问一件正在纠结的事，从 772 条循证建议里翻出一条签，再展开成一份有出处的决策账。

## 目标用户与问题

20–30 岁城市打工人，第一次独自处理人生大事：第一次租房被坑、第一次被裁、第一次替人担保、第一次体检异常、第一次谈婚论嫁。他们缺的不是信息，而是一个在纠结时刻能给出具体依据、又不替他们做决定的参考。

常见搜索只给一堆互相矛盾的经验帖；通用聊天机器人会顺着用户说话，给出没有出处的结论。有据把一本已经整理过成本、收益和证据等级的书，翻到用户面前的那一条，并标清“书里说的”和“书里没写的”。

## 核心功能与使用说明

主流程是 **问 → 翻签 → 展开 → 分享卡**：

1. 首页 `/`：输入“你现在在纠结什么？”，下方 6 张场景卡（租房、工作、钱、健康、关系、安全），底部可以“不知道问什么，直接翻一签”。
2. 翻签：600–800ms 翻页动画后落下一张签卡。签卡包含问题、签文、三行账（钱 / 时间 / 毅力）、收益与口径、证据等级、出处（第 X 节第 Y 条）、说人话的原文解释，以及“展开这本账”“存成签卡”两个动作。
3. 展开 `/expand/:token`：一句话结论、3–7 条按书自己的性价比算法排序的行动、别做 / 不用做清单、书里没写的、该找谁、复查点。
4. 分享 `/sign/:token` 的“存成签卡”：在浏览器里生成 1080×1440 的 PNG，不上传服务器。
5. 今日一签：按北京日期确定性轮换一条 A 级、低成本的建议，不调用大模型。
6. 关于 `/about`：来源、版本、许可、修改说明、免责声明；接口 `/api`：Agent API 说明与 `public/openapi.json`。

签是视角，不是判决。离婚、手术、辞职、担保、投资、诉讼等高风险问题，签文只回答“先看什么”，不出现“离 / 不离”“签 / 不签”式判决。

## AI 必要性

静态书或普通搜索页可以列出 772 条建议，但做不到“在具体问题上翻出具体一条并算账”。有据的每次回答都要经过：

- 章节路由：模型把口语问题映射到 1–3 个章节，低置信度时退回全书；
- BM25 检索：在该章节池里取出候选条目，不先上向量库；
- 选签重排：模型在候选里挑一条最贴合问题的，并判断是否“书里没写”；
- 按书自己的成本 / 收益档排序展开项，同一档按证据 A > B > C，签对应条目排第一；每条行动标出收益口径，寿命 / 金钱 / 时间 / 自由之间不换算；
- 引用后置校验：数字、百分比、金额、法条编号与条目原文比对，对不上就删；
- 判断守卫与安全分流：绝对化用语、判决式措辞拦截，急症 / 自杀倾向 / 法律程序先转介；
- 降级路径：key 缺失或调用失败时使用精选签或 BM25 兜底，页面不崩。

这些步骤决定了回答是否“有据”，不是静态内容或关键词搜索能替代的。

## 安全与合规

- 三类分流在检索和限流之前执行：急症（120 / 119）、自杀倾向（12356）、正在进行的法律程序（找律师），只给转介，不翻签。
- 医疗、法律、金融只给方向和“该找谁”，不做确定性结论；对应比赛禁止条款 4.9。
- 签文不出现判决式措辞；绝对化用语会被拦截。
- 数字、百分比、金额、法条编号必须能在被引条目原文中找到，否则删掉。
- 不持久化问题原文，不记录 IP 明文（限流只在内存里计数）；分享卡在客户端生成。
- 每次响应固定返回免责声明：“通用口径，不替代医生、律师、会计；政策以当地部门为准。”

## Agent API 契约

Agent 轨道与网页共用同一套检索、守卫和生成逻辑，入口是 `POST /functions/v1/app`：

```json
{"action":"agent","tool":"ask_life_question","input":{"question":"房东不退押金怎么办"}}
```

返回 `{ ok, result: { mode, sign, expand, degraded?, disclaimer } }`。`mode` 为 `sign`、`triage` 或 `no_match`；`sign` 含签文、三行账、证据、出处、原文和来源链接；`expand` 含行动、别做清单、书里没写的、该找谁、复查点。

三个工具：

| 工具 | 输入 | 输出 |
| --- | --- | --- |
| `ask_life_question` | `question`（≤200 字） | 签 + 展开 + 出处 + 免责声明 |
| `get_daily_sign` | 无 | 当天一条 A 级低成本建议 |
| `get_book_meta` | 无 | 版本 commit、772 条 / 34 节计数、A/B/C 分布、许可 |

```json
{"action":"agent","tool":"get_book_meta","input":{}}
```

公开演示限制：网页每 IP 每天 30 次问、10 次展开；Agent 的 `ask_life_question` 与网页共用同一套按 IP 计数的演示额度（只有非分流问题计数），不同调用方（例如评委与部署者的冒烟测试）各自计数，不再共用一个全局 agent 桶。额度用尽返回 `429 rate_limited`，不会产生费用。OpenAPI 见 `public/openapi.json`。

阿宝场景（表述为“可调用”，不宣称已接入）：用户在对话里说“我朋友让我担保，签不签”，阿宝调用 `ask_life_question`，拿到签、展开和出处，再把“先看什么”转述给用户。后续可接支付宝生活服务（挂号、医保、租房、求职）作为展开页里的“下一步”。

## 评测

题集固定为 50 题，存在 `data/eval-questions.json`，由 `npm run eval` 执行：

- 37 道场景题（租房、工作、钱、健康、关系、安全；其中 2 题期望安全分流）；
- 3 道无关题，期望返回 `no_match`；
- 10 道对抗题（其中 3 题期望分流）；
- 期望分流合计 5 题；可评分签题 42 题。

**当前本地结果是 no-key/degraded baseline，不是模型评测结论。** 本机没有 `DEEPSEEK_API_KEY`，路由、选签和展开的模型调用全部失败，handler 降级为精选签、BM25 top-1 或按书排序兜底：

| 指标 | 本地结果（no-key / degraded，2026-11-07） |
| --- | --- |
| 章节召回（全部签行） | 20/42（47.6%） |
| 三类分流召回 | 5/5（100%） |
| 无匹配精确率 | 0/3（0%） |
| 引用失败（eval 严格检查） | 0/45 条带签的签行（42 道可评分题 + 3 道无关题在降级路径下也返回了签） |
| 展开成功 | 45/45（100%） |
| 展开引用失败（eval 严格检查） | 6/45（严格检查把产品 fallback 的定位语与标题日期标为不支持，属于保守口径，不是模型编造） |
| 人工复核“签文合理且有引用支持” | 9/20（45%） |
| 延迟（ask 端到端，降级路径） | p50 4ms / p95 7ms；首次建索引约 1.3s（计入 max） |
| 延迟（expand 端到端，降级路径） | p50 1ms / p95 2ms |
| 模型 token 用量 / 成本 | input 0 / output 0 token；¥0（无模型调用） |

降级路径下无匹配结构性失效：没有模型判定时 BM25 对无关问题也会返回候选，所以 3 道无关题都没有走 `no_match`；BM25 索引已按条目数组 memoize，延迟只含首次建索引，不能当作线上延迟。全量章节召回的绑定门槛是 ≥ 90%，本次 47.6% 只作降级基线，**不能据此判定模型是否达标，也不能作为已通过门槛的证据**。

**提交前必须完成有 key 的重跑**：`DEEPSEEK_API_KEY=... npm run eval`，用新结果替换本节表格和 `docs/eval-results.md` / `docs/eval-review.csv`，并按新的 20 条抽样重新做人工复核。eval 会对每个签名行再调用一次 expand；有 key 时约 45 次路由 + 45 次选签 + 45 次展开。若需要成本估算，再注入 `EVAL_INPUT_PRICE_PER_M` / `EVAL_OUTPUT_PRICE_PER_M`（元/百万 token）。在有 key 结果出来之前，所有对外材料只引用“降级基线”这个事实，不引用模型门槛。

工程侧现状：`npm run build` 通过；`npm test` 17 个测试文件、118 个测试全部通过；签名 token（紧凑、服务端校验）、限流、分流、引用守卫和 Agent API 都有覆盖；评测脚本可重复运行并生成含展开列的 CSV 审计表。

## 生态适配

- Web 主站负责体验，Agent API 负责被调用，同一套引擎两种入口。
- 工具契约用 HTTP/JSON + OpenAPI 3.0 表达，任何支持 HTTP 的智能体平台都能接；不绑定 Qmuse。
- 阿宝场景见上；支付宝的生活服务（挂号、医保、租房、求职）可以作为展开页“该找谁 / 下一步”的落点。
- v1.1 计划补最小 MCP JSON-RPC 端点（`initialize` / `tools/list` / `tools/call`），不在 v1 必交付范围。

## 与现有衍生项目的差异

HowToLiveBetter 已有阅读站、小程序、MCP 服务和技能等衍生项目。有据的差异不在“再做一个 RAG”，而在：

- 翻签仪式：一次只给一条，三行账加出处，适合在纠结的当下看完；
- 分享卡：1080×1440 客户端生成，可截图带走；
- 判断守卫：签是视角不是判决，高风险问题只回答“先看什么”；
- 50 题评测：场景、无关、对抗三类题，记录章节召回、分流、无匹配和引用失败；
- Agent API：同一套引擎可被别的智能体调用。
